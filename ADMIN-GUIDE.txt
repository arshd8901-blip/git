JOBLY ADMIN GUIDE (you are the moderator)
=========================================

You manage everything from the Supabase dashboard -> Table Editor. No extra admin page is needed.
Log in at supabase.com/dashboard, open your project, click "Table Editor".

REVIEWING A NEW JOB (do this for EVERY submission)
  1. Table Editor -> jobs -> filter status = pending.
  2. Open the row. Open job_private for the same job_id to see the employer's contact email.
  3. CHECK, in this order:
     [ ] The business is real: search its name + city, find its website / Google listing / social page.
     [ ] The email domain matches the business (not a free gmail/outlook for a "big" company).
     [ ] The apply link goes to the employer's own site (https only).
     [ ] Pay is at least the local minimum wage and clearly stated. No "up to $5,000/week".
     [ ] No fees, gift cards, equipment purchases, or "send us your SSN/bank info".
     [ ] The minimum age fits the work. Common sense for under-18s: no alcohol service (rules vary),
         no heavy machinery, no roofing, no driving as the main job, no late-night shifts on school nights.
         Rules differ by state. Check your state labor agency and the U.S. Dept. of Labor (dol.gov).
     [ ] The description reads like a real person wrote it.
  4. If it passes: set status = approved. If you are confident the employer is real (you confirmed
     who they are, e.g. by calling or emailing the business), also tick employer_verified = true.
     This shows the blue "Employer verified" badge. Jobs without it show "Not yet verified".
  5. If it fails: set status = rejected (the employer sees "Not approved" under Your submissions).
     Consider emailing them why.
  Approved jobs appear on the site right away (refresh).

ADDING A JOB YOURSELF
  Table Editor -> jobs -> Insert row. Required: title, company, city, job_type, work_style, min_pay,
  max_pay, hrs_min, hrs_max, min_age (16/17/18), description. Set status = approved.
  Optional: zip, lat/lon (needed for the distance filter on real jobs), shifts, tasks, apply_url, season.
  shifts format: an array of codes like {Mon-A,Wed-A,Sat-M}  (A = afternoon/after school, M = morning, E = evening)
  tasks format: {Greet customers,Prepare drinks}
  season: summer or holiday (leave empty for year-round). Tick is_flexible if there are no fixed shifts.

REMOVING A JOB
  Set status = rejected (hides it, keeps a record) or delete the row.
  Jobs that are filled or expired should be hidden promptly.

REPORTS (check at least every few days)
  Table Editor -> reports. job_ref = the job's id (look it up in jobs). Reasons "Asks for money or
  fees" and "Looks like a scam" are URGENT: set that job to rejected immediately, then investigate.
  Delete report rows once handled.

CONTACT MESSAGES
  Table Editor -> contact_messages. Reply to the email in the row. Topic "Delete my data":
  1) Authentication -> Users -> find the person by email -> delete the user. Their saved data
     (user_data) deletes automatically. 2) Reply to confirm.
  For parent/guardian questions, reply promptly and politely and offer deletion if they want it.

GOOD HOUSEKEEPING
  * Keep a simple log (a spreadsheet) of who you verified and how.
  * Never share the project's secret/service_role key or database password with anyone.
  * Enable two-factor sign-in on your Supabase and GitHub accounts.
  * Supabase free projects pause after a week of inactivity: log in occasionally, or upgrade
    before launching widely.
  * Back up your jobs table now and then (Table Editor -> export as CSV).

LOCATION / DISTANCE
  The distance filter knows a few sample ZIP codes (see ZIPS in index.html). For other areas, add
  their ZIP centers to the ZIPS list in index.html (lat/lon of each ZIP; search "zip code lat lon"),
  and fill lat/lon on the job rows. Teens' ZIPs are never stored or sent anywhere.


NEW IN v4
  * Teens can now share a link that opens a specific job (#job=<id>), so check that approved jobs look right
    in the job window: that is the page people will see first.
  * Interest tiles and the map group jobs by keywords in the title/company/description. If a job lands in the
    wrong group, adjust its wording. No database change is needed.
  * Practice notes and checklist progress live in user_data (columns checklist, practice). Only each user can read them.


USING THE ADMIN PAGE (v6)  -  START HERE
  1. Make yourself an admin (one time). Sign up/in on the site with your admin email first. Then Supabase -> SQL Editor ->
     New query, paste this with YOUR login email, and Run:
         insert into public.admins (user_id) select id from auth.users where email = 'YOUR-LOGIN-EMAIL';
     Refresh the site: More -> Admin appears. (Only people in the admins table ever see it. The database enforces this.)
  2. Jobs tab: pending jobs with the employer's private contact email and apply link. Check the business is real, the
     apply link goes to that business, pay is at least minimum wage, and the age is right. Then Approve, Approve and mark
     verified (a badge teens see), or Reject. "Recently approved" lets you Take down a listing later.
  3. Employers tab: people asking to browse teen profiles. Open their website, then Verify or Reject. You can remove access later.
  4. Reports & messages tab: reported profiles (Hide this profile), reported job listings, and contact messages (with their
     email to reply). Press Mark handled when done.
  5. Profiles tab: every profile, searchable. Hide or Unhide. Check it now and then for anything inappropriate.

EMAIL ALERTS (v6)  -  OPTIONAL, ABOUT 15 MINUTES
  How it works: when something happens (new job, new employer, new report, a request to a teen, an approval) the database adds a
  row to a table called outbox. A small function (supabase/functions/send-emails/index.ts) sends those rows as emails.
  Honest limits: free email services only deliver to arbitrary people (teens, employers) from a domain YOU own. Without one,
  you can still get alerts yourself. So there are two stages:

  STAGE 1: ALERTS TO YOU (free, no domain)
   1. resend.com -> sign up with the email where you want alerts. Dashboard -> API Keys -> Create API Key -> copy it.
   2. Supabase -> Edge Functions -> Deploy a new function -> Via Editor. Name it exactly: send-emails
      Delete the sample code, paste ALL of supabase/functions/send-emails/index.ts from this folder, click Deploy.
   3. Supabase -> Edge Functions -> Secrets (Edge Function Secrets). Add these four, then Save:
         MAIL_API_KEY  = the Resend key from step 1
         MAIL_FROM     = Jobly <onboarding@resend.dev>
         ADMIN_EMAIL   = the SAME email you used to sign up to Resend (Resend's test sender only delivers to that address)
         SITE_URL      = https://arshd8901-blip.github.io/jobly_full_website/     (or your new domain)
   4. Supabase -> Integrations -> Cron (turn it on if asked) -> Create job. Name: send-emails. Schedule: every 5 minutes.
      Type: Supabase Edge Function -> choose send-emails -> Create.
      If the job's runs show a 401 error: Edge Functions -> send-emails -> Details/Settings -> turn OFF "Verify JWT".
      That is safe here because the function only sends emails that are already queued, and returns just counts.
   5. Test: on the live site, send a message from the Contact page. Within about 5 minutes you should get "[Jobly] New contact message".
      Nothing? Edge Functions -> send-emails -> Logs. Also Table Editor -> outbox: the "error" column explains failures.
   You'll get at most one alert of each kind per 10 minutes, so an attacker can't flood your inbox.

  STAGE 2: EMAILS TO TEENS AND EMPLOYERS (needs a domain you own, about $10-15 a year)
   1. Buy a domain (Namecheap, Cloudflare, Porkbun...). In Resend -> Domains -> Add Domain -> copy the DNS records into your
      domain's DNS settings -> Verify. (The sender must be on that verified domain.)
   2. Edit the secret MAIL_FROM to:  Jobly <hello@yourdomain.com>
   3. Add the secret  SEND_USER_EMAILS = true
   Now teens get "An employer is interested in you" (no message text, no contact details), employers get "A teen accepted" and
   approval/rejection notices. Until you do this, those emails are skipped (not stored up), and teens still see requests
   in My profile.
   Alternative: Brevo (set secret MAIL_PROVIDER = brevo and a Brevo API key). Brevo also needs your own domain for good delivery.
   Note: Supabase's sign-up/password emails are separate; see GROWTH-GUIDE.txt (SMTP) for those.

TEEN PROFILES AND EMPLOYER ACCESS (v5)  -  THE SAME TASKS BY HAND IN THE TABLE EDITOR
  1. VERIFY EMPLOYERS. Supabase -> Table Editor -> employers. New rows are status = pending. Look at the company and
     website (open the site, check it is a real business, ideally reply to them through the Contact route you trust).
     Set status = verified to let them browse teen profiles, or rejected. Only verified employers can see profiles.
     To remove access later, set status back to rejected.
  2. CHECK REPORTS. Table Editor -> profile_reports (profile_id is the teen's user_id). To hide a profile at once, open
     Table Editor -> profiles, find that user_id and tick hidden_by_admin. The teen can't undo it. Also read contact_messages.
  3. REMOVE ANYONE. Deleting a row in profiles removes that profile, its shared resume, contact email and requests.
  4. LOOK AT NEW PROFILES SOMETIMES. Open the profiles table now and then. Anything fake, rude, or sharing contact info or a
     school: tick hidden_by_admin. The database already blocks emails, links and phone numbers typed normally, but people
     can write numbers out in words, so a human check matters.
  5. Be strict with employers at the start. A small number of real, checked employers is better than many unchecked ones.
